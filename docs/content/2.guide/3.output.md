The working copy is always SQLite. Resume and duplicate checks need it. `--format` chooses what else you see.

## sqlite

```bash
avherald-scraper --format sqlite
```

This is the default. The only file is `data/avherald.sqlite`.

## cli

```bash
avherald-scraper --format cli --limit 3
```

The headlines are printed in the terminal, with blank lines between the number, the category and date, the headline, and the URL. Use this for a small limit. No extra file is written. The SQLite file is still updated.

## json, csv, and xlsx

```bash
avherald-scraper --format json
avherald-scraper --format csv
avherald-scraper --format xlsx
```

The export is written next to the database, with the same name:

- `data/avherald.json`
- `data/avherald.csv`
- `data/avherald.xlsx`

Each file contains every row in the database, not only the rows from this run. Open the CSV or the workbook in Excel, Numbers, or Pages.

`.pages` is not written. Apple Pages uses a private package, and a file built here would not open.

## Columns

| Column | Meaning |
| --- | --- |
| `article_id` | 8 hex characters, the key |
| `url` | `https://avherald.com/h?article=<id>` |
| `heading` | Listing headline |
| `list_date` | Date line as printed on the site |
| `list_date_iso` | `YYYY-MM-DD` |
| `icon` | For example `incident.gif` |
| `category` | `crash`, `accident`, `incident`, `news`, or `report` |
| `source_page` | List URL that contained the row |
| `first_seen_at` | First time this id was stored |
| `last_seen_at` | Last time this id was seen |

A later run updates the heading, dates, icon, and category. `first_seen_at` stays.
