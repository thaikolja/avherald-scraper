Settings come from three places. The first one that sets a value wins:

1. The command-line flag.
2. `config.ini` in the project root, or the file you pass to `--config`.
3. Built-in defaults.

Leaving a flag off does not erase the value in `config.ini`.

## Edit the file

Open `config.ini`. Booleans are `true` or `false`. A line that starts with `;` is a comment and is ignored.

```ini
[crawl]
limit = 10
sort = update

[storage]
format = sqlite
```

The full file, as it is in the repository, is on the [config.ini](/reference/config-ini) page. That page is regenerated from the file every time the docs are built.

## Common flags

| Flag | Meaning |
| --- | --- |
| `-n`, `--limit` | How many new headlines to keep |
| `-c`, `--category` | `crash`, `accident`, `incident`, `news`, `report` |
| `--sort` | `update` or `occurrence` |
| `-o`, `--db` | SQLite file used for resume |
| `--format` | `sqlite`, `json`, `csv`, `xlsx`, or `cli` |
| `-d`, `--delay` | Seconds between list pages. Default 3 |
| `--proxy` | Repeat for more than one proxy |
| `--fresh` | Start at the first list page again |
| `--dry-run` | Do not write |
| `-q`, `--quiet` | No progress bar and no summary |

`--show-config` prints the merged result and exits.
